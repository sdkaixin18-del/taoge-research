## 已落地的数据桥

`market_observer.py`复用已安装监控包的公开行情适配器、交易日历和本地静态参考表，使用自己的SQLite、原始归档及systemd服务。主监控源码未改；现有提醒范围和公社补充查询保留。

| 项目 | 当前行为 |
|---|---|
| 全市场 | 当前参考名单5,576只A股；全扫每轮结束后等待60秒，默认100只一批、并发2。盘中运行，闭市不请求。 |
| 观察池 | 已触板、距涨停价2%以内及有债正股；观察轮每轮结束后等待30秒。不是逐笔行情。 |
| 转债 | 全扫读取参考表内311只债；观察轮读取观察池对应债。映射存在不等于债当天有效可交易。 |
| 基准 | 上证、深成、创业板、中证转债指数、转债ETF；指数与ETF只解析价格，成交量口径另行核实。 |
| 履历 | 首次观察已封、从未封到首次观察触板、两次不同源时刻确认的开板/回封；断线和午休单列，不能还原真正首封时间。 |
| 保存 | 独立最新报价、观察状态/事件及7天原始归档；原主数据库只读。没有新增新闻表、通知队列或模型接口。 |
| 本地读取 | `fetch_snapshot.py`复用已有SSH配置执行只读导出，原子写入本地JSON。它不读取或输出密钥内容。 |

本地读取命令，在本仓库目录执行：

```sh
python3 监控分析/fetch_snapshot.py --out 课程视频/服务器监控分析/latest_snapshot.json
```

SSH默认读取本机`~/.ssh/config`，也可通过本地配置或`--ssh-config`指定。复制[配置示例](client_config.example.json)为`client_config.local.json`再填写本机路径，该文件已被Git忽略。不得把SSH配置、主机地址、凭据或真实行情归档提交到公开仓库。Windows执行命令见接入说明，读取脚本不再包含Mac绝对路径。

采集器测试在Linux/Mac使用安装了原监控包及依赖的Python环境执行；Windows客户端只需标准库，运行读取桥的测试：

```sh
python -m unittest discover -s 监控分析 -p 'test_*.py'
# Windows客户端：py -3 -m unittest discover -s 监控分析 -p 'test_fetch_snapshot.py'
```

独立采集器已部署并启用；服务模板见[cb-market-observer.service](cb-market-observer.service)。服务器文件位于用户级应用和数据目录。此仓库保留部署源文件，**定时研究只读，不执行部署、配置修改或服务重启**。

## 还缺哪些数据

| 数据 | 当前情况和下一步 |
|---|---|
| 所有涨停及无债队友 | 已补完整股票名单轮询、最新报价、日内触板集合和观察履历。13只本次报价不满足有效涨停价/成交条件，覆盖不得填成100%。 |
| 板块扩散 | 已有静态全量题材缓存和涨停交集；还需题材成员历史版本、全体成员涨跌/成交分母、排除自身的队友变化。静态概念不是当日涨停原因。 |
| 大盘和债市 | 已补5个最新基准；完整同步1/5分钟仍按需在本地补取，当前数据库不是标准分钟库。ETF与债指数不计为两个独立因子。 |
| 真正首封和封单 | 轮询仅给观察时刻；需稳定授权的首封、逐笔/更细盘口源才能提高精度。现有单档/双档快照不能推导排队成交。 |
| 股债分钟与债性 | 当前有最新报价、盘口和原始归档；完整分钟、历史流动性分布、价格响应及费用情景需补充，不能从日线高低点推出先后。 |
| 债的有效状态 | 已有映射、转股价和余额资料；还需最后交易日、强赎/回售、停牌与临停状态及公告生效时间的系统校验。余额披露日不明时保留未知。 |
| 新闻与事件关系 | 保留原服务端公社3条展示；新增主动检索、事实核实、来源版本及事件—个股映射只在本地保存。 |
| 验证与运行 | 闭市链路已通过；首个真实交易日的覆盖、延迟、开板/回封及重启去重待验收。完整模式成功、失败、漏报和主动放弃继续积累。 |

实测一次全扫的股债响应体约1.32MB，另有基准请求及协议开销；按每分钟一轮估算约317MB/交易日，再加观察轮。这个估算不是实测全天总流量，应在真实交易日记录请求量与磁盘占用后再优化，优先复用主监控数据而非提频。
